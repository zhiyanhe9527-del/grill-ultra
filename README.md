# Grill Ultra

一个面向 **项目启动前的需求访谈与拆解** 的 Codex 技能，通过逐轮提问，把模糊意图、待解决的问题或初步计划转化为具体、可验证的用户需求。

通过有来源的候选需求单帮助用户纠偏，再逐轮追问真正的缺口。需求明确后，先审核正式确认单，再审查方案；未经最终共识确认，不开始实施。

## 使用

将本仓库中的 `SKILL.md`、`references/` 和 `agents/` 放入你的 Codex 技能目录下的 `grill-ultra/` 文件夹。

不需要先写好需求文档或方案。可以从一个项目方向、一个困扰，甚至“想做但还没想清楚”开始。在 Codex 中显式调用：

```text
$grill-ultra 我准备开展一个项目：【描述项目方向或想解决的问题】。请在开始实施前，通过分轮提问帮我挖掘并拆解具体需求，明确目标、成功标准、使用场景、约束、边界和关键前提，形成需求确认单供我审核。
```

也可以根据当前起点调用：

- **只有方向**：`$grill-ultra 我想做【方向】，但还没想清楚需要什么。请通过提问帮我形成具体需求。`
- **只有问题**：`$grill-ultra 我遇到了【问题】，还不确定该做什么项目。请先审问问题与前提，再帮我拆解需求。`
- **已有初步需求**：`$grill-ultra 开工前，请通过提问检查这份需求的遗漏、歧义和冲突，并整理成可确认的需求单：【内容】`
- **已有方案**：`$grill-ultra 请先核对这个方案背后的真实需求，再按项目规模审查方案与取舍：【内容】`

优先使用选择题并保留自由填写入口；需求和最终共识确认前，不直接进入项目实施。

界面显示名为 **Grill Ultra**，技能标识为 `grill-ultra`。这是独立技能，不依赖旧版 `grill-me` 或 `grilling`。

## 工作方式

1. **框架审计**：判断需求规模，区分事实、假设和偏好，完成第一次归零测试。
2. **候选需求单**：先展示有来源的草案，未知内容保持待确认。
3. **阶段 A**：按依赖关系分轮澄清，通常 3–5 问、最多 6 问；能查的事实由代理自行查。
4. **正式需求确认单**：五块审核，保留用户原话、显式标注 AI 推断，允许局部打回。
5. **阶段 B**：完整需求进行第二次归零测试及方案压力测试；轻量需求跳过 B。
6. **最终共识**：用户明确认可方案和取舍后才实施。

## 特点

- 九种审阅视角按阶段轮值，普通轮次只启用 2–3 个角色。
- 六字段需求卡片持续显示进度；卡片状态与整单审核状态分开记录。
- 优先使用选择题与自填区；原生工具不支持时明确降级为文字。
- 自填最多两层探索，同一节点最多一次复述确认，仍未确认则暂停。
- 用户原词保留：已确认内容进摘要，待澄清内容进相关选项。
- 连续自填触发候选设计自检，不直接认定用户或选项有错。
- 不把“想要某项需求”误当成同意增加预算或延后交付。

## 验证与限制

主流程与模板经过结构校验，并对轻量、重需求、自填模糊、反复自填、跨轮矛盾、确认单打回和工具不支持表单七类场景做过规则走查。

规则走查不是自动化行为保证。交互控件和子代理可用性取决于运行环境；本技能不承诺参考图片的精确布局，也不会让静态网页输入自动回传聊天。

## 设计沿革

由原有 `grilling` 的设计树、frontier 轮次推进、事实自主查证和共识确认机制扩展而来，加入候选单优先、需求生成、角色审阅及有界自填澄清。
